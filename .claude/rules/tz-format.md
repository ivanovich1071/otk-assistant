# Требования по изготовлению (ТЗ)

Второй документ системы. Карта обмера делается по одному чертежу, ТЗ — по всему
комплекту: сборочный чертёж, спецификации, подсборки и детали в одном PDF.

Эталон структуры — `tests/gold/tz/МШЕФ 02.6.02.07.00.000/tz.docx`.

## Структура документа

```
ТРЕБОВАНИЯ ПО ИЗГОТОВЛЕНИЮ
<обозначение> <наименование>

Общие данные:
  • <строки, выведенные из обозначения, штампа и спецификации>

Технические требования чертежей
<обозначение> <наименование>
  1. <пункты ТТ сборочного чертежа>
Вес – <масса>

Спецификация
<обозначение> <наименование>
[таблица: № на сборке | Обозначение | Наименование | Кол-во | Примечание]

<для каждой подсборки по порядку в спецификации:>
  N. <обозначение> СБ <наименование>
  Технические требования:
    1. <пункты>
  Вес – <масса>
  Спецификация:
  [таблица]
  <детали этой подсборки:>
    <обозначение> <наименование>
      1. <пункты ТТ детали>
    Вес – <масса> | Материал – <материал>

ТРЕБОВАНИЯ К ДЕТАЛЯМ (ПОЛНАЯ ДЕТАЛИЗАЦИЯ)
Детали основной сборки:
  <детали корневой сборки в том же виде>
```

Разделы спецификации (`Сборочные единицы`, `Детали`, `Стандартные изделия`) идут
строками-заголовками внутри таблицы. Раздел `Документация` заголовком не выделяется.

## Контракт `work/tz.json`

```json
{
  "source": "input/комплект.pdf",
  "designation": "МШЕФ 02.6.02.07.00.000 СБ",
  "title": "Барабан натяжной 140.80-100",
  "mass": "956 кг",
  "general": ["Барабан натяжной;", "Ширина ленты – 1400 мм;"],
  "assembly": {
    "designation": "...", "title": "...", "level": 0, "pos": "",
    "page": 1, "spec_page": 2, "mass": "956 кг",
    "tech_requirements": [{"no": "1", "text": "* Размеры для справок."}],
    "spec": [{"section": "Детали", "pos": "4", "designation": "...",
              "name": "Шайба торцовая", "qty": "2", "note": "0,6 кг",
              "material": ""}],
    "parts": [{"designation": "...", "title": "...", "page": 3, "qty": "2",
               "mass": "0,6 кг", "material": "Лист 8 ГОСТ 19903-74, Ст3сп ГОСТ 14637-89",
               "tech_requirements": []}],
    "children": []
  },
  "warnings": ["..."]
}
```

| Поле | Значение |
|------|----------|
| `assembly` | корень дерева; вложенность — через `children` |
| `pos` | номер подсборки в спецификации родителя |
| `page` / `spec_page` | номера листов исходного PDF, для трассировки |
| `mass` | всегда с единицей: `956 кг` |
| `material` | из штампа детали; у детали без чертежа — из графы наименования спецификации |
| `warnings` | расхождения, которые должен посмотреть человек |

## Откуда что берётся

| Данные | Источник |
|--------|----------|
| обозначение, наименование, масса, масштаб, материал, формат | штамп чертежа (ГОСТ 2.104) |
| технические требования | нумерованный блок над штампом |
| состав, количество, массы | лист спецификации (ГОСТ 2.106) |
| дерево сборки | спецификации; обозначение — только запасной путь |

Состав определяют **спецификации, а не обозначения**. Совпадение префикса
обозначения — подсказка, а не доказательство вхождения.

## Общие данные

Единственный раздел, который не переписывается с чертежа, а выводится:

- наименование изделия без типоразмера — `Барабан натяжной;`
- параметры, зашифрованные в типоразмере: `140.80-100` → `Ширина ленты – 1400 мм;`
  и `Диаметр барабана – 800 мм (по обозначению «80»);`
- покупные узлы, определяющие изделие: `Подшипниковые узлы – тип 3520 ГОСТ 5721-75;`
  (из раздела «Стандартные изделия» спецификации)
- `Общая масса сборки – 956 кг.` — из штампа корневой сборки

Строки заканчиваются `;`, последняя — `.`.

## Канон технических требований

На чертеже двоеточия, точки с запятой и дроби часто нарисованы графикой, а не
текстом, поэтому из PDF приходит `Общие допуски по ГОСТ 30893.1-2002 H14, h14,
± IT14 2 .`. Приведение к канону — не «улучшение чертежа», а восстановление того,
что на нём нарисовано.

| Из PDF | В документе |
|--------|-------------|
| `Размеры для справок.` | `* Размеры для справок.` |
| `-места строповки` | `◙ Места строповки.` |
| `... 30893.1-2002 H14, h14, ± IT14 2 .` | `... 30893.1-2002: H14; h14; ±IT14/2.` |
| `"Литол-24". ГОСТ 21150-87` | `«Литол-24» ГОСТ 21150-87` |
| `Термообработка: улучшение НВ 190-220.` | `Термообработка: улучшение, НВ = 190…220.` |
| `Длина развёртки 2463 мм.` | `Длина развёртки – 2463 мм.` |
| `Размер в скобках после сборки.` | `Размер в скобках – после сборки.` |

Таблица живёт в `tools/tz_canon.py` и правится текстом. Всё, что таблица не
покрыла, приводит в порядок модель — но **смысл менять нельзя**: числа, марки
материалов, номера ГОСТ переносятся как есть.

## Чего в ТЗ не делаем

- не пересчитываем массы и не проверяем их арифметику;
- не дописываем требования «от себя», даже если на чертеже их явно не хватает;
- не убираем расхождения между штампом и спецификацией — они идут в `warnings`
  (например, «Крышка глухая: 3,8 кг по штампу, 3,7 кг по спецификации»).
