# Ассистент ОТК · OTK Assistant

**Автогенератор карт обмера и заданий на изготовление по чертежу**

Репозиторий: https://github.com/ivanovich1071/karty-obmera

> О названии. Рабочее «Карты обмера» описывало формат документа, а не работу.
> «Ассистент ОТК» называет службу, которой система помогает, и понятен любому
> на производстве без пояснений. Латинское написание — **OTK Assistant**,
> оно же используется в путях и именах файлов, где кириллица неудобна.

---

## Проблема

Организация размещает заказы на небольших заводах и в цехах Китая. У таких
подрядчиков **нет контрольно-измерительных машин и 3D-сканеров** — размеры
контролируются вручную, штангенциркулем и микрометром по бумажному бланку.

Чтобы провести выходной контроль (ОТК), технолог должен подготовить два документа:

1. **Карту обмера** — чертёж с красной сквозной нумерацией всех размеров и
   таблицу в Word, где против каждого номера стоит значение по чертежу и пустая
   графа под фактический замер.
2. **Задание на изготовление** — выжимку из комплекта чертежей: состав изделия,
   массы, материалы, технические требования по каждой детали.

Обе задачи делались вручную: разметка номеров в Photoshop, перенос значений
в Word, сборка задания по стопке чертежей. **От 2 до 6 часов на чертёж**
в зависимости от сложности — при потоке 10–15 чертежей в месяц это до двух
рабочих недель, потраченных на перепечатывание того, что уже нарисовано.

Работа при этом монотонная и ошибкоопасная: потерянная звёздочка справочного
размера, кириллическая `Н` вместо латинской `H` в поле допуска, пропущенный
размер — всё это уходит на завод и возвращается браком.

## Пользователь

**Технолог и инженер ОТК** организации, размещающей заказы на внешних
производствах. Один человек, работающий на своём ноутбуке с Windows.

Второй, косвенный пользователь — **контролёр на заводе-изготовителе**: он
получает готовую карту обмера и заполняет графу фактических значений.

## Основная функция

Система превращает чертёж в комплект документов ОТК. Два режима.

### Режим 1 — карта обмера (по одному чертежу)

| | |
|---|---|
| **Вход** | чертёж: PDF, PNG, JPG, TIFF, BMP, WebP, GIF — векторный или скан |
| **Что делает** | находит все надписи на листе, читает их, отделяет размеры от штампа, технических требований и заголовков видов, разбивает по видам и разрезам, нумерует по правилам предприятия, наносит красные номера на чертёж и собирает таблицу в Word по шаблону |
| **Выход** | размеченный JPG + карта обмера `.docx` + отчёт проверки |

### Режим 2 — требования по изготовлению (по комплекту)

| | |
|---|---|
| **Вход** | сводный векторный PDF комплекта: сборочный чертёж, спецификации, подсборки, детали |
| **Что делает** | читает штампы, спецификации и технические требования из текстового слоя, строит дерево изделия по спецификациям, раскладывает массы и материалы по деталям, приводит формулировки к каноническому виду, помечает расхождения |
| **Выход** | документ `.docx`: общие данные, технические требования, таблицы спецификаций, требования к каждой детали с весом и материалом |

### Инструменты внутри

- **Компьютерное зрение** — поиск надписей на растре: бинаризация, удаление
  длинных линий морфологией, фильтр штриховки и стрелок, группировка глифов
  в строки с определением поворота.
- **Разбор текстового слоя PDF** — у векторных чертежей надписи, штампы и
  спецификации читаются точно и бесплатно, без распознавания.
- **Vision-модель** (`qwen/qwen3.7-plus` через OpenRouter) — читает надписи
  со сканов, где текстового слоя нет.
- **Правила предметной области** — четыре текстовых файла в `.claude/rules/`:
  порядок нумерации, словарь спецсимволов, что переносить в техтребования,
  контракт обмена данными. Правятся без программирования.

**Главный принцип: модель — глаза, код — геометрия и правила.** Координаты,
поиск свободного места под номер, порядок позиций, сборка документов —
всё детерминированно. Модель только читает надписи и не решает, где кончается
один вид и начинается другой.

## Формат результата

Пользователь получает в окне приложения и в выбранной папке:

1. **Размеченный чертёж** — исходный лист с красными номерами возле каждого
   размера, в JPG. Открывается прямо в приложении с зумом и панорамированием.
2. **Карту обмера** `.docx` — таблица по шаблону предприятия: `№ п/п`,
   `Значение по чертежу`, пустые графы под фактические замеры, отдельной
   секцией технические требования.
3. **Требования по изготовлению** `.docx` — для комплекта чертежей.
4. **Отчёт проверки** — список замечаний: дубли номеров, разрывы нумерации,
   расхождения между штампом и спецификацией, позиции с низкой уверенностью.

Всё это видно в приложении до скачивания: таблицу можно просмотреть, поправить
значения, убрать лишние позиции и пересобрать документы одной кнопкой.

## Технологии

| Слой | Что использовано |
|------|------------------|
| Язык | Python 3.13 |
| Компьютерное зрение | OpenCV, NumPy |
| Работа с PDF | PyMuPDF |
| Документы Word | python-docx, шаблоны, вырезанные из реальных карт |
| Веб-сервер | FastAPI, uvicorn |
| Интерфейс | HTML + CSS + чистый JavaScript, без сборки и без внешних библиотек |
| Оконная версия | pywebview |
| Модель | `qwen/qwen3.7-plus` через OpenRouter, ответы в JSON |

Одна модель на весь проект. Двухмодельная схема с дорогой `max` на перепроверку
была отвергнута замером: стоимость чертежа выросла с $0,054 до $0,20 —
вчетверо, — не изменив результат ни на одну позицию.

## Что измерено

Все цифры получены прогонами на реальных заказах, а не оценкой.

**Требования по изготовлению**, «Барабан натяжной 140.80-100», 20 листов:

| Показатель | Результат |
|-----------|-----------|
| Позиций комплекта | **19 из 19** |
| Строк спецификаций | **21 из 21** |
| Веса и материалы | расхождений с эталоном нет |
| Раздел «Общие данные» | совпал с эталоном дословно |
| Стоимость | **$0** для векторного PDF |

Система нашла и то, что человек в ручном задании сгладил: у «Крышки глухой»
в штампе 3,8 кг, а в спецификации 3,7 кг. Расхождение не исправляется молча,
а попадает в замечания.

**Карта обмера**, векторный сборочный чертёж: 19 размеров из 19, стоимость $0.

**Карта обмера**, рукописный скан «Колесо зубчатое 161.00.009»:

| Показатель | Результат |
|-----------|-----------|
| Надписей прочитано | **202 из 202** |
| Позиций совпало с ручной картой | 9 из 20 |
| Стоимость чертежа | $0,054 |

На сканах система пока помощник, а не автомат: контактные листы и черновая
разметка экономят время, но карту нужно просмотреть и поправить — для этого
в приложении и сделан редактор.

**Покрытие архива.** Из 537 чертежей в рабочем архиве **196 векторных
(561 лист, 36 %)** обрабатываются бесплатно и точнее модели, 341 скан
требует чтения моделью.

## Эффект

Было: **2–6 часов** ручной работы на чертёж.
Стало: минуты на обработку плюс просмотр результата человеком.
Стоимость: **$0** для векторных чертежей, **около 5 центов** для сканов.
